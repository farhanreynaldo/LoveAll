# LoveAll host test

Start with one real session in your own group. Let the person who normally organizes the court drive LoveAll on their phone. If that is you, ask one player to watch for confusion and write brief notes. Record what happens before asking for opinions. Then repeat with hosts outside your group if the core flow holds up.

## First session with your group

1. Before play, open LoveAll on the organizer's phone, add the real roster, and start a doubles session. Time how long it takes to see the first matchup. Do not explain the controls to the organizer.
2. Use LoveAll to choose and score at least three actual matches. Do not manufacture a late arrival, break, or departure during play. If one happens, use the matching attendance control and note what changed.
3. Before one match, ask: “Would you play this matchup?” If the host changes it, record the proposed four, the chosen four, and their reason. Ask the question before offering your own fairness opinion.
4. If no attendance change happens naturally, use a five-minute dry run after play: add a late player, mark a waiting player on break and back, then mark someone as left. Do this after ending the real session or in a separate test session so the real score history stays intact.
5. End the real session and check the recap. On the next session, check that the group roster can be reused. Ask whether the host would use LoveAll again next week and what would stop them.

Use [PILOT_NOTES.md](PILOT_NOTES.md) to capture the result. A screenshot of a disputed matchup plus the attendance and waiting counts is more useful than a general “felt unfair” judgment. Ask everyone before recording names or screenshots, and replace names with initials when sharing feedback.

## Later tests with other hosts

Run this with five people who organize a recurring doubles session on one court. Use their own phones. Observe without explaining the controls. Record what happens before asking for opinions.

## Setup

Give each host the current LoveAll URL. Ask them to imagine a real session with seven named players. Do not describe the rotation rule or point out the attendance controls. Have their usual method available for the same tasks afterward.

## Tasks

1. Add seven players and start a doubles session. Record time from opening the app to seeing the first matchup.
2. Ask who is waiting and why these four were chosen. Record the host's answer before explaining anything.
3. Start and score two matches. After the second starts, say an eighth player has arrived. Ask the host to add them.
4. Say one waiting player is taking a break. Ask the host to mark it, then finish the current match. Check that the player on break is absent from the next matchup and received no waiting credit.
5. Say that player returns, then another player leaves before the following match. Check that the proposed matchup contains only available players.
6. Ask the host to choose a different matchup. Watch whether they find **Change matchup**, set four distinct players, and understand that their choice is preserved.
7. End the session and ask what they would expect LoveAll to remember for next week.
8. Repeat tasks 3–6 with the host's current method. Let them compare the effort in their own words.

## Record for each host

| Observation | Record |
| --- | --- |
| Time to first matchup | Seconds |
| Time to handle arrival, break, departure | Seconds for each change |
| Errors or help requested | Action and exact point of confusion |
| Did they understand who waited? | Their words before any explanation |
| Matchups they overrode | Original, replacement, reason |
| Trust in the next matchup | 1–5, then ask why |
| Tool they would use next week | LoveAll, current method, or neither; why |
| Would they pay for a recurring group? | What saved work or history would justify it; do not suggest a price first |

Ask at the end: “Which decision felt unfair?” and “What would you need to see before trusting the next matchup?” Capture exact phrases for the next interface change and ad copy.

## Decision after five sessions

Fix any attendance error or lost score before another test. If at least two hosts override the same kind of matchup, revisit that ranking rule with the recorded cases. If hosts accept the lineup but cannot explain it, improve the explanation before changing the scheduler. If setup or score entry blocks the task, fix that path before spending on Meta ads. Keep the first ad promise tied to behavior hosts actually observed.
